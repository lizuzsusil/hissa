Redesign the **entire UI/UX and visual design language of the application** from the ground up. The goal is to create a polished, modern, cohesive, production-quality interface that feels intentional, intuitive, premium, and consistent across the whole product.

### 1. Overall Design Direction

Establish a completely unified design language across the application rather than making isolated visual changes. Review the existing interface and identify outdated, inconsistent, cluttered, or confusing patterns, then redesign them with a clear and systematic visual approach.

The new design should feel:

* Modern and sophisticated
* Clean and minimal without feeling empty
* Professional and trustworthy
* Visually balanced
* Easy to understand at a glance
* Consistent across every screen and interaction
* Responsive and accessible
* Premium and production-ready

Avoid unnecessary decoration, excessive gradients, excessive shadows, inconsistent corner radii, random colors, or visual elements that do not contribute to usability.

### 2. Design System

Create a coherent design system and apply it consistently throughout the application.

Define and standardize:

* Primary, secondary, accent, success, warning, error, and neutral colors
* Background and surface colors
* Typography hierarchy
* Font sizes, weights, line heights, and letter spacing
* Spacing and sizing scale
* Border radius system
* Border styles and colors
* Shadow/elevation system
* Iconography
* Button styles
* Form controls
* Cards
* Badges and tags
* Tooltips
* Dropdowns
* Modals/dialogs
* Tabs
* Navigation elements
* Tables and lists
* Empty states
* Loading states
* Error states
* Notifications/toasts

Do not introduce one-off styles when an existing design-system pattern can be reused.

### 3. Layout & Visual Hierarchy

Improve the overall layout structure so every screen has a clear visual hierarchy.

Pay particular attention to:

* Page headers
* Navigation
* Content width
* Grid and column structure
* Section spacing
* Alignment
* Information density
* Primary vs. secondary actions
* Grouping related information
* Whitespace
* Responsive behavior

Users should immediately understand **where they are, what they can do, what is most important, and what action they should take next**.

### 4. Navigation & UX

Rework navigation wherever necessary to make the product easier to understand and use.

Ensure:

* Navigation is predictable and consistent
* Active states are obvious
* Important actions are easy to find
* Navigation hierarchy is logical
* Breadcrumbs or contextual navigation are used where helpful
* Mobile navigation is properly designed
* Users receive clear feedback after interactions

Reduce unnecessary clicks and cognitive load wherever possible.

### 5. Components

Redesign the application's reusable components so they feel like part of one unified product.

Every component should have clearly defined:

* Default state
* Hover state
* Focus state
* Active state
* Disabled state
* Loading state
* Error state where applicable

Components should be reusable, composable, and visually consistent rather than individually styled on each screen.

### 6. Forms & User Input

Improve forms with a strong emphasis on usability and clarity.

Use:

* Clear labels
* Helpful placeholders only where appropriate
* Proper field grouping
* Clear required/optional indicators
* Inline validation
* Helpful error messages
* Clear success feedback
* Appropriate input types
* Logical tab/focus order
* Accessible focus states

Make forms feel simple and approachable rather than dense or intimidating.

### 7. Tables, Lists & Data-Dense Screens

Improve information-heavy interfaces without sacrificing readability.

Use:

* Strong column hierarchy
* Appropriate spacing
* Clear row states
* Sorting/filtering patterns
* Search where useful
* Pagination or progressive loading where appropriate
* Sticky headers when beneficial
* Responsive alternatives for smaller screens

Prioritize scannability and make important information visually prominent.

### 8. States & Feedback

Design all important UX states rather than only the ideal/default state.

Include thoughtful designs for:

* Loading
* Empty
* Error
* Success
* Offline/network failure
* No search results
* Disabled functionality
* First-time use
* Confirmation
* Destructive actions

Feedback should be immediate, understandable, and proportional to the importance of the action.

### 9. Accessibility

Follow modern accessibility principles throughout the redesign.

Ensure:

* Sufficient color contrast
* Visible keyboard focus states
* Appropriate text sizing
* Accessible form controls
* Clear error messaging
* Logical semantic hierarchy
* Touch targets large enough for comfortable interaction
* Color is never the only way information is communicated

The interface should work well for keyboard, mouse, touch, and assistive-technology users.

### 10. Responsive Design

Redesign the interface to work naturally across:

* Desktop
* Laptop
* Tablet
* Mobile

Do not simply shrink the desktop layout. Reconsider layouts, navigation, controls, tables, cards, spacing, and content hierarchy for smaller screens.

### 11. Micro-interactions

Add subtle, purposeful interactions that improve the perceived quality of the product.

Use restrained:

* Hover transitions
* Button feedback
* Focus transitions
* Expand/collapse animations
* Modal transitions
* Toast animations
* Loading indicators
* Skeleton states

Animations should be fast, subtle, and functional—not distracting.

### 12. Consistency Audit

Before considering the redesign complete, audit the entire application for inconsistencies.

Look for:

* Different button styles
* Inconsistent spacing
* Different border radii
* Inconsistent typography
* Duplicate component patterns
* Inconsistent colors
* Misaligned elements
* Inconsistent icon sizes
* Different interaction behaviors
* Inconsistent empty/loading/error states

Replace these with standardized design-system patterns.

### 13. UX Improvements

Do not limit the work to visual styling. If an existing screen has confusing information architecture, poor hierarchy, unnecessary steps, unclear actions, or awkward interaction patterns, improve the UX as part of the redesign.

Preserve the application's core functionality while improving **clarity, usability, efficiency, and overall user experience**.

### 14. Final Quality Bar

The final application should look and feel like a **single, professionally designed product**, not a collection of independently designed screens.

Every screen should feel like it belongs to the same design system.

Prioritize:
**clarity → hierarchy → consistency → usability → accessibility → visual polish.**

Do not make changes merely for the sake of making the UI look different. Every design decision should have a clear UX or visual rationale.

Before implementing individual screens, establish the global design language and reusable component patterns first, then apply them systematically across the entire application.
